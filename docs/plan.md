# 메신저 구축·검증 계획

## 목표와 경계

Rocky Linux 10 계열 VM의 Node 중앙 서버와 Windows·Android·Web 클라이언트를 구축한다. 메일 서버 인증·사용자 그룹 경계를 유지하고, 메시지 안정성과 낮은 서버 사양에서의 동작을 검증한다. 집 밖에서 사설 서버에 접속하는 기능은 범위에서 제외한다.

## 단계

1. 대상 메일 서버의 공식 인증·관리자 권한 조회 방법과 테스트 환경을 확인한다. 서버 배포·실시간 통신·저장 기술은 이 단계에서 정한다.
2. 인증 후 같은 메일 서버 사용자끼리만 대화하도록 서버 경계를 구현한다. 개인·단체 대화, 파일 전송, 읽음 상태를 추가한다.
3. Windows·Android·Web 클라이언트를 구현한다. 기술과 코드 공유 방식은 착수 전에 결정한다.
4. 메일 서버 관리자 권한으로 보존 기간을 설정하고, 만료 메시지·파일 삭제와 실패 재시도를 검증한다.
5. Android·Windows 앱 프로세스 종료 상태의 알림을 시험한다. 외부 푸시 중계·추가 서비스 비용 없는 방식을 우선 검토한다. 필수 알림을 충족할 수 없으면 구현 직전에 대체 방식을 사용자와 재결정한다. Web 알림은 구현하지 않는다.
6. 연결 끊김·재접속, 서버 재시작, 메시지 유실·중복·순서, 전달 상태 복구를 검증한다.
7. 낮은 사양의 서버 VM을 하나로 고정하고 같은 하드웨어·데이터·부하 조건에서 소프트웨어 구성을 비교한다. 처리량·지연·오류·자원 사용량과 병목을 기록한다.

## 완료 확인

- 메일 서버별 사용자 경계, 대화·파일·읽음 기능과 보존 기간이 실제 클라이언트에서 동작한다.
- 재연결·재시작·부하 시험의 결과와 실패 사례를 재현할 수 있다.
- Android·Windows 종료 상태 알림의 가능 범위와 선택한 방식을 실제 기기에서 검증한다.
- 민감정보를 로그와 공개 자료에 포함하지 않는다.

## 이후 결정

메일 서버 인증 프로토콜, 실시간 통신·저장·배포·클라이언트 기술, 서버 VM 사양, 부하 합격 수치, 알림 방식과 강제 종료·절전 상태의 처리 범위는 해당 단계 전에 정한다.
