# 기능 명세서

> 현재 구현의 최신 사용자 조건은 [실행 현황](12-execution-status.md)을 따른다. 특히 F28에서 메시지 본문 만료만으로 아직 유효한 첨부를 삭제하지 않는다. 메일 연동 시험과 Android 작업/시험은 수행하지 않는다.

작성일: 2026-10-02. [기능 목록 F01~F47](09-feature-list.md)의 목표, 입력·출력의 의미, 확인 Test와 로깅 방식을 정의한다. 작성 근거는 [요구](01-requirements.md)·[모듈](03-modules.md)·[통신](04-communication.md)·[코드](05-code-rules.md)·[운영](06-operations.md)·[전환](07-rebuild-plan.md)이다. **확인 방법의 명세이며 기능 구현·시험 결과가 아니다.**

## 공통 해석

input/output에는 실제 계정·ID·주소·본문·시간·용량의 예시 값을 넣지 않는다. 필드 이름과 그 의미만 기술한다. 제약의 수치·API·스키마는 기존 통신·코드·운영 문서를 따른다.

| 공통 항목 | 의미 |
| --- | --- |
| CTX | 서버가 세션 검증으로 만든 요청 문맥. `userId`는 행위자, `serverId`는 인증된 메일 서버 경계, `sessionId`는 폐기 가능한 내부 세션 참조, `requestId`는 서버가 생성한 요청 추적값. 클라이언트가 임의로 설정하는 권한 입력이 아님 |
| PAGE | `cursor`는 목록 조회를 이어갈 불투명 위치, `limit`은 정책 상한 안의 요청 개수 |
| 목록 출력 | 업무 항목 목록, `nextCursor`는 다음 조회 위치, `snapshotCursor`는 읽은 DB 상태의 이벤트 시점. 필요하지 않은 필드는 해당 API 계약을 따름 |
| 오류 출력 | `code`는 실패 종류, `message`는 안전한 설명, `requestId`는 추적값. stack·비밀·내부 경로를 포함하지 않음 |
| 작업 출력 | 처리 상태, 성공·보류·실패 건수, 재개 위치와 다음 실행 조건. 실행 완료와 작업 적재 완료를 구분 |
| 시험 환경 | 단위는 주입 시계·port, 계약은 스키마·DTO, 통합은 실제 파일 DB·임시 파일 저장소, E2E는 실제 브라우저/앱, 운영은 격리 VM·부하/복원 환경 |

API의 성공 응답·DB 변화·수신 화면을 직접 검사한다. 실패 시험은 오류뿐 아니라 **금지된 쓰기·외부 호출·이벤트가 발생하지 않았음**도 검사한다. crash 시험은 중단 지점을 고정하고 재시작 뒤 중복·누락·재개 여부를 비교한다. F01~F47은 각각 해당 ID의 test case 묶음으로 연결한다.

## 공통 기능확인 로깅 방식

- 앱 서버는 Pino 구조화 로그를 stdout/stderr로 내보내고 journal로 보관한다. 감사 대상은 별도 `audit_events`에 기록한다. 스크립트는 같은 식별·결과 필드의 실행 로그를 남긴다.
- 공통 필드는 발생 시각·수준·서비스·release·모듈·사건명·`featureId`·`outcome`이다. 요청은 `requestId`, 배치는 `jobId`와 원래 요청/실행 추적값으로 연결한다. 기능표의 사건명은 이번 명세에서 정한 식별자이며 현재 구현된 로그가 아니다.
- 아래의 ID·건수·사유·버전 등은 허용 필드만 기록한다. `sessionId`, 세션 원문/해시, cookie, bearer, signed cursor 원문, 푸시 토큰, 비밀번호, 이메일, 메시지 본문, 원본 파일명, 파일 내용은 기록하지 않는다. 오류·사용자 입력 문자열도 그대로 기록하지 않는다.
- 정상 완료·업무 거부는 `info`, 회복 가능한 장애·재시도·자원 경고는 `warn`, 최종 실패·무결성 위반은 `error`다. 반복 거부·재시도는 집계하여 로그 폭주를 막는다. 서버가 신뢰할 수 없는 대상 ID는 기록하지 않는다.
- UI 기능은 로컬 진단·테스트 수집으로 확인한다. 원격 UI 로그 전송 기능을 추가하지 않는다. 로컬에도 본문·자격 증명을 기록하지 않는다.
- 각 Test는 로그도 수집해 `featureId`·추적값·사건 순서·최종 결과·필수 필드를 확인하고 비밀값 비노출을 검사한다. 로그 출력만으로 기능 성공을 판정하지 않는다. 시험 결과는 별도 증거에 기능/시험 ID·실행 환경·기대·관찰·판정·한계를 기록한다.

### F01

**허용 메일 서버 목록·주소 해석** · identity · 1차 · 근거: R02·R03 / 요구·통신

| 항목 | 명세 |
| --- | --- |
| 목표 | 운영자가 등록한 메일 서버를 사용자에게 제시하고 입력한 주소/별칭을 등록된 서버 경계로 해석한다. |
| 목표-input | 등록 서버 목록: 로그인 가능한 서버 정의. 사용자 주소/별칭: 로그인 대상을 선택하려는 식별 정보. 등록 호스트·TLS 설정: 실제 인증 연결에 사용할 서버 내부 정보. |

| 기능확인 Test방식 | 계약·단위: 등록 목록/별칭만 반환·해석, 미등록 주소 거부. 통합: 미등록 입력에 외부 연결이 없고 응답에 내부 호스트·TLS 비밀이 없음. |
| 기능확인 로깅방식 | `identity.servers.listed`, `identity.server.resolved`: 결과 건수 또는 해석된 서버 ID·결과·사유 code. raw 입력 주소·설정 제외. 거부 시험에서 외부 인증 시작 로그도 없음 확인. |

### F02

**메일 계정 로그인·사용자 등록** · identity · 1차 · 근거: R02 / 요구·통신 · 실통합 U01

| 항목 | 명세 |
| --- | --- |
| 목표 | 실제 메일 계정을 검증하고 해당 서버의 사용자와 메신저 세션을 생성한다. |
| 목표-input | `serverId`: 선택한 등록 서버. `username`: 해당 제품 규칙의 계정명. `password`: 일회 인증 비밀. 메일 인증 port·TLS 신뢰·timeout 정책: 외부 검증 조건. |
| 목표-output | 사용자 식별·서버 경계·표시 정보와 세션 만료 시각. 브라우저에는 보호 cookie가 발급되고 DB에는 세션 hash와 사용자 관계 저장. 실패는 자격 증명 거부와 접속 장애를 구분한 안전한 오류. |
| 기능확인 Test방식 | 통합: 유효 인증 후 사용자 upsert·세션 생성, 재로그인에도 사용자 중복 없음. 잘못된 계정·비밀번호, TLS 오류·timeout·DB 실패는 세션 미생성. U01 확정 뒤 실제 계정·제품 정규화 시험. |
| 기능확인 로깅방식 | `identity.login.completed`: 성공 시 서버·내부 사용자 ID·소요시간, 거부/장애 시 안전한 사유 code·결과. 메일 원문·계정·비밀번호·세션 hash 제외. 실패와 DB rollback 로그를 같은 요청으로 확인. |

### F03

**세션 검증·현재 사용자 확인** · identity · 1차 · 근거: R02·R03 / 모듈·통신

| 항목 | 명세 |
| --- | --- |
| 목표 | 활성 세션의 사용자만 요청을 수행하도록 검증하고 서버가 신뢰할 CTX를 만든다. |
| 목표-input | cookie 또는 네이티브 bearer: 전달된 세션 증명. 현재 시각·세션 저장 상태: 만료·폐기 판정 근거. 요청 추적값: 결과 상관관계. |

| 기능확인 로깅방식 | `identity.session.checked`: 결과·사유 code, 성공 시 내부 사용자·서버 ID. 요청 완료 로그와 연결하고 세션 참조·token·hash를 제외. 반복 거부는 집계. |

| 기능확인 로깅방식 | 서버 `identity.logout.completed`, 로컬 `client.state.cleared`: 결과·정리 항목 건수·연결 종료 사유. 세션값·초안 제외. 종료 후 이전 문맥의 업무 성공 로그가 없음 확인. |

## 명세를 구현으로 옮길 때

목록의 단계·조건을 유지하고 각 기능 ID 아래 시험 case를 정상/거부/경계/중단 복구로 나눈다. 필요한 case만 실제 test suite에 연결한다. event명과 metadata를 logger allowlist에 등록하고 생성 계약과 기능표를 함께 갱신한다. U01~U04로 결정되지 않은 기기/알림 필드는 이름·값을 임의 확정하지 않는다.

확인 결과는 응답·DB/파일 상태·실제 화면/OS 관찰·로그 증거를 함께 남긴다. 조건 미확정·미구현·미실행은 통과로 기록하지 않는다.
