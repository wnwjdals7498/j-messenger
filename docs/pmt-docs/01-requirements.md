# 요구사항과 완료 기준

> 이번 실행의 최신 범위와 정책은 [실행 현황](12-execution-status.md)을 따른다. Web·Windows와 VM 메시징을 우선 구현하며 메일 연동 시험·Android 작업은 제외한다. 메시지 본문 5일·파일 14일은 독립 보존이다. 아래 R목록은 장기 요구 이력으로 유지한다.

## 원천과 해석

원천은 [기존 계획](../plan.md)의 목표·후속 기능, [기존 환경](../env.md), [웹 명세](../tasks/web.md), [서버 명세](../tasks/server.md)다. 코드로 구현된 범위와 요구사항의 범위는 다르다.

| ID | 유지할 요구사항 | 원문 | 완료 증거 |
| --- | --- | --- | --- |
| R01 | Rocky Linux VM의 중앙 서버, 허용된 사설망 접속 | plan 목표·E1~E8 | 허용망 접속, 비허용망 차단, 재부팅 후 서비스 복구 |
| R02 | 사용자가 지정한 메일 서버와 계정으로 인증 | plan 목표·S9, 기존 README | 실제 계정 2개 인증, 실패·TLS 오류 처리 |
| R03 | 같은 메일 서버 사용자끼리만 조회·대화 | plan 목표·S5·A | 다른 서버의 사용자·대화·메시지·파일·이벤트 접근 차단 |
| R04 | 개인·단체 대화, 기록 영속화 | plan 목표·S3~S7 | 두 브라우저 송수신, 새로고침·서버 재시작 후 기록 유지 |
| R05 | 재전송 중복 방지, 재접속 누락 복구 | plan S7 | 응답 유실 후 재시도에도 한 건, 끊긴 동안의 기록 복구 |
| R06 | 파일 전송 | plan 후속 1 | 참여자 업로드·다운로드, 타 서버 차단, 실패 파일 정리 |
| R07 | 읽음 상태 | plan 후속 2 | 사용자별 읽음 위치 단조 증가, 여러 기기·재접속 일치 |
| R08 | 메일 서버 관리자가 메시지·파일 보존 기간 설정 | plan 후속 3 | 해당 서버의 관리자만 변경, 만료 자료 삭제·중단 재개 |
| R09 | Web·Windows·Android 클라이언트 | plan 후속 4, 기존 README | 각 클라이언트 로그인·대화·파일·읽음 계약 시험 |
| R10 | Windows·Android 프로세스 종료 상태 알림 목표 | plan 후속 4·마지막 문단 | 상태별 실기기 시험, 달성 불가 조건과 선택한 대안 명시 |
| R11 | 외부 푸시 중계 없이 추가 서비스 비용 없는 방식을 우선 검토 | plan 마지막 문단, 기존 README | 공식 플랫폼 제약 검토 후 선택 근거 기록 |
| R12 | 한국어 UI, UTC 저장·전송, 서울 시간 표시 | plan C5·C6 | 표시·시간 경계·한글 입력 시험 |

R02의 주소 입력은 서버 운영자가 등록한 호스트·별칭을 `serverId`로 해석한다. 사용자가 보낸 임의 호스트·포트로 서버가 접속하지 않는다. [기존 plan S2](../plan.md)의 허용 메일 서버 목록과 함께 적용하는 해석이다. 이메일 도메인 문자열만으로 같은 메일 서버라고 판정하지 않는다.

## 단계와 범위

- 1차: R01~R05·R12. HTTPS/WSS, 실제 메일 인증과 저장·복구까지 포함한다. 개발용 인증 통과만으로 완료하지 않는다.
- 2차: R06~R08. 파일·읽음·보존 정책을 동일한 서버 경계 안에 추가한다.
- 3차: R09~R11. 앱 기능을 연결하고 종료 알림의 실현 가능성과 실제 동작을 판정한다.
- 제외: Web 알림, 외부 인터넷 공개 접속, 서버 간 대화, 통화·화상·봇·검색·종단간 암호화. 추가하려면 요구사항부터 갱신한다.

## 기존 동작 기준

텍스트는 앞뒤 공백 제거 후 JavaScript `string.length` 기준 1~4000자다. Enter 전송, Shift+Enter 줄바꿈, 한글 조합 중 Enter는 전송하지 않는다. 화면은 데스크톱 목록·대화 분할, 640px 이하 목록·대화 전환을 유지한다. Android도 UTF-16 코드 단위 기준으로 계약을 맞춘다.

1차 사용자 목록은 해당 서버에 정상 로그인한 이력이 있는 사용자다. 전체 메일 주소록 가져오기는 원문에 확정되지 않았으므로 구현에 포함하지 않는다. 1차 그룹은 생성 시 참여자를 고정하고, 추가·탈퇴·과거 기록 열람 정책은 기능 확장 때 별도 정의한다.

## 확인이 필요한 입력

| ID | 필요한 정보·판단 | 영향 |
| --- | --- | --- |
| U01 | 메일 제품·버전, 허용 호스트·포트·TLS CA, 계정 표기 규칙, 시험 계정 | 실제 인증 어댑터 선택과 R02·R03 판정 |
| U02 | 메일 관리자를 증명하는 제품 API 또는 운영자의 검증된 서버별 역할 매핑 | 보존 설정 권한. IMAP 로그인 성공만으로 관리자 권한 부여 금지 |
| U03 | 파일 크기·형식·서버별 용량, 메시지·파일 보존 일수 | 파일·보존 기능 활성화 조건. 무제한을 기본값으로 간주하지 않음 |
| U04 | 폰의 허용 사설망 접근 경로, 대상 OS·배포 방식, 종료 알림의 허용 대안 | 호스트 전용 VM 주소를 폰에서 접근 가능하다고 가정하지 않음 |

U01~U04는 해당 단계만 제한한다. 확정 정보 없이 운영 인증·삭제·외부 푸시를 활성화하지 않으며, 구조·계약·모의 시험은 진행할 수 있다.
